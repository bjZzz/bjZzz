## 2. 系统概述

### 2.1 业务背景

医疗机构在代谢性、心脑血管、呼吸性三类疾病及共病科研中，面临数据来源分散（HIS/LIS/PACS/院外平台）、术语标准不统一、患者跨机构身份难关联、科研队列构建效率低、数据质量难保障、分析工具与安全合规要求高等问题。本系统旨在建设**共病专病一体化科研数据平台**，支撑多中心数据采集、治理、存储、检索、分析与项目管理。

### 2.2 业务目标

1. **数据汇聚**：打通院内院外、静态动态多源数据，形成全生命周期健康数据视图。
2. **标准治理**：建立跨病种术语、字典、清洗与映射体系，提升数据可比性与可用性。
3. **专病共病建库**：构建三类专病库及可配置共病库，支撑多病种联合研究。
4. **科研赋能**：提供队列管理、随访、统计分析与风险模型，缩短科研周期。
5. **安全合规**：满足数据脱敏、加密、审计及数据不出库分析等合规要求。

### 2.3 用户角色

| 角色 | 职责描述 |
| --- | --- |
| 系统管理员 | 机构/用户/权限配置，系统运维 |
| 数据管理员 | 数据接入、清洗规则、字典维护、入库运维 |
| 质控审核员 | 数据质量监控、差异复核、补录审核 |
| 科研项目负责人 | 课题设计、队列管理、进度监控 |
| 科研人员 | 数据检索、提取、统计分析、报告生成 |
| 临床录入员 | CRF 录入、数据补录、随访执行 |
| 分中心协调员 | 本分中心数据上传、补录与协作 |

#### BR-01-01 多源数据采集与对接

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-01-01-01 ~ REQ-01-01-09 |
| **涉及角色** | 数据管理员、分中心协调员 |

**业务描述**

系统需支持从医院内部业务系统（HIS、LIS、PACS、EMR）及外部平台（全民健康系统、政务平台）自动或半自动采集共病科研所需的临床数据，并根据数据时效性要求配置差异化同步策略，保障多中心协作下的数据一致性与及时性。

**业务场景**

1. 数据管理员配置与 HIS/LIS 的接口对接，系统自动采集患者基本信息、检验、医嘱等数据。
2. 分中心通过标准 Excel 模板或 API 上传本分中心结构化数据。
3. 针对危急值场景配置准实时同步；针对历史归档数据配置 T+7 周级同步；针对日常诊疗数据配置 T+1 日级同步。

**业务规则**

- 必须支持 HL7、FHIR、DICOM 等主流医疗互操作协议及数据库直连方式。
- 外部数据须经 ETL 清洗、转换、归一化后入库，不可绕过治理流程直接写入专病库。
- 回顾性数据采集须保留原始来源标识，支持规则引擎审核。
- 同步策略可按数据源独立配置，支持全量与增量两种模式。

**验收标准**

- [ ] 至少完成 HIS、LIS 两类系统的对接验证
- [ ] 三类同步周期（T+7/T+1/准实时）均可独立配置并正常运行
- [ ] 分中心可通过模板或 API 成功上传数据并被正确解析
- [ ] 采集数据覆盖基本信息、病史、体征、影像、检验、医嘱等维度

#### BR-01-02 结构化专病数据录入

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-01-02-01 ~ REQ-01-02-11 |
| **涉及角色** | 临床录入员、科研项目负责人 |

**业务描述**

为代谢性、心脑血管、呼吸性三类疾病提供符合权威指南的结构化 CRF 录入能力，支持可视化表单设计、多题型采集、逻辑跳转与量表自动计分，确保科研数据采集的标准化与完整性。

**业务场景**

1. 科研负责人基于指南指标设计糖尿病/高血压/慢阻肺专病 CRF 表单。
2. 录入员在随访现场填写表单，系统自动计算 CAT、mMRC 等量表总分。
3. 患者上传检验报告附件（PDF/DICOM 等），系统支持在线预览。

**业务规则**

- 专病表单必填字段须参照《中国糖尿病防治指南（2024 版）》等权威指南。
- CRF 控件不少于 10 种，附件支持 18 种以上格式。
- 逻辑跳转基于前序题目回答动态显隐，不可导致必填项被永久隐藏。
- 量表计分公式可配置，计算结果实时展示且不可手动覆盖（除非有修正权限）。

**验收标准**

- [ ] 三类疾病核心指标均已覆盖（见功能清单明细）
- [ ] 表单设计器支持拖拽/点选两种建题方式
- [ ] 逻辑跳转、布局切换、量表计分均验证通过
- [ ] 附件上传与预览覆盖文档/图片/压缩包/DICOM 格式

#### BR-01-03 数据标准化与字典管理

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-01-03-01 ~ REQ-01-03-23 |
| **涉及角色** | 数据管理员、质控审核员 |

**业务描述**

建立跨病种数据清洗、术语映射、非标准归一化及标准化字典体系，解决多源异构数据在格式、单位、编码、术语上的不一致问题，形成可复用的数据治理规则库与字典资产。

**业务场景**

1. 数据管理员配置血糖异常值阈值及单位转换规则（mg/dL → mmol/L）。
2. 系统将「心梗」「冠心病」等非标准术语自动映射至 ICD-10 I20-I25。
3. 字典中检验指标定义变更后，关联 CRF 表单收到联动更新提示。

**业务规则**

- 关键字段缺失须分级处理：关键指标可配置合理值填充，非关键字段仅做缺失标记。
- 异常值识别须结合统计方法（IQR/Z-score）与临床逻辑双重校验。
- 去重规则须基于患者唯一标识 + 核心字段组合，不可误删有效历史记录。
- 术语库须覆盖 ICD-10/11、LOINC 等标准体系。
- 字典变更须可追溯，关联模块须支持联动或提示。

**验收标准**

- [ ] 四类清洗规则（缺失/异常/重复/格式单位）均可配置并生效
- [ ] 三类疾病术语库可维护、可检索
- [ ] 非标准术语归一化规则验证通过率 ≥95%（抽样测试）
- [ ] 诊断/治疗/检验/症状四类字典库完整可用
- [ ] 字典变更联动 CRF 模块验证通过

#### BR-01-04 统一患者主索引（EMPI）

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-01-04-01 ~ REQ-01-04-05 |
| **涉及角色** | 数据管理员、科研人员 |

**业务描述**

建立跨机构、跨系统的统一患者主索引，整合患者历次就诊数据，实现患者唯一标识与多标识关联，支撑共病科研中的患者级数据串联与全景视图。

**业务场景**

1. 同一患者在 A 院与 B 院的就诊记录通过身份证号自动关联为同一 EMPI。
2. 缺乏身份证号时，系统基于姓名+电话+地址等特征进行模糊匹配并提示人工确认。
3. 科研人员查看某患者跨机构完整诊疗时间轴。

**业务规则**

- 多标识匹配（身份证/医保号/健康码）准确率须 ≥99.8%。
- 模糊匹配结果须支持人工确认/否决，不可静默合并。
- 匹配算法权重与阈值须可配置，变更须留痕。
- 主索引为患者级数据关联的唯一入口，下游模块不得绕过。

**验收标准**

- [ ] 已知测试集上标识匹配准确率 ≥99.8%
- [ ] 模糊匹配 + 人工确认流程验证通过
- [ ] 同一患者跨系统数据可在 360 视图中完整展示
- [ ] 匹配规则配置界面可用且变更可追溯

#### BR-05-02 代谢性疾病专病数据库

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-05-02-01 ~ REQ-05-02-03 |
| **涉及角色** | 科研项目负责人、科研人员、数据管理员 |

**业务描述**

构建代谢性疾病（以糖尿病为代表）专病数据库，涵盖患者信息、病历、检验、治疗、随访等结构化存储，提供库级概览统计与患者级详情展示，支持动态字段扩展及外部系统数据回写。

**业务场景**

1. 科研人员查看代谢病专病库患者总量、地域/年龄分布概览。
2. 点击某糖尿病患者，查看其糖化血红蛋白、糖耐量、并发症等完整专病档案。
3. 影像组学平台将分析结果通过标准接口回写至专病库。

**业务规则**

- 每位患者须有唯一标识，关联全部子库数据。
- 病历资料须支持全文检索。
- 检验结果库须支持动态字段扩展，不改底层表结构。
- 专病模板可自定义，系统动态生成库表。

**验收标准**

- [ ] 7 类子库结构完整，数据可正确关联
- [ ] 概览图表（患者数/队列数/分布）数据准确
- [ ] 糖尿病专病详情四类数据完整展示
- [ ] 外部数据回传接口联调通过

#### BR-05-05 共病数据库

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-05-02-10 ~ REQ-05-02-18 |
| **涉及角色** | 科研项目负责人、科研人员 |

**业务描述**

通过可视化配置共病组合规则（如「糖尿病 AND 冠心病」），系统自动跨专病库关联抽取数据，生成共病队列数据库，并提供共病谱系分析、队列画像及跨病种详情聚合展示。

**业务场景**

1. 科研负责人定义「A 病确诊后 5 年内并发 B 病」的时间窗共病规则。
2. 系统自动生成共病队列，展示两病共现频率。
3. 查看「糖尿病合并冠心病」患者跨病种检验与影像，点击跳转原报告。

**业务规则**

- 共病规则须支持 AND/OR/NOT 及时间窗约束。
- 共病视图须随底层专病数据更新实时同步。
- 跨病种详情页须融合两病种基础档案，保留各维度独立展示。
- 检查结果须可跳转至原专病库报告原文。

**验收标准**

- [ ] 共病规则配置界面可用，规则引擎正确筛选队列
- [ ] 共病谱系、队列画像、质量监控三类概览正确
- [ ] 「糖尿病+冠心病」详情聚合展示验证通过
- [ ] 报告联动跳转功能正常

#### BR-05-06 专病库运营驾驶舱与患者全景

| 属性 | 内容 |
| --- | --- |
| **优先级** | P1 |
| **关联需求** | REQ-05-02-19 ~ REQ-05-02-29 |
| **涉及角色** | 数据管理员、科研项目负责人、科研人员 |

**业务描述**

提供专病库运营驾驶舱（简报、待办、审计、运营指标）及患者级洞察分析（特征画像、360 视图、诊疗时间轴、数据溯源），支撑管理者决策与临床科研人员的患者级深度分析。

**业务场景**

1. 管理员登录驾驶舱，查看全库患者总量、在研项目数及待办补录任务。
2. 科研人员筛选「BMI≥28 且年龄 45-65 岁」亚群，查看箱线图分布。
3. 查看某患者 360 视图，检验趋势中危急值高亮，点击溯源至 LIS 原始检验单。

**业务规则**

- 驾驶舱数据须实时或准实时刷新。
- 待办中心须聚合项目/补录/随访三类任务。
- 360 视图异常值须特殊标记，溯源链路须完整到源系统单据。
- 值域归并（如年龄段合并）操作仅影响展示层，不修改原始数据。

#### BR-20-01 机构与用户管理

| 属性 | 内容 |
| --- | --- |
| **优先级** | P0 |
| **关联需求** | REQ-20-01-01 ~ REQ-20-02-04 |
| **涉及角色** | 系统管理员 |

**业务描述**

支持多层级机构架构（省-市-区县）、中心/分中心关系配置，以及用户账号、角色、状态的全生命周期管理。

**业务场景**

1. 管理员创建「XX 市分中心」并关联至「XX 省中心」。
2. 为分中心录入员创建账号并分配「数据录入员」角色。
3. 冻结离职人员账号。

**业务规则**

- 机构须区分中心与分中心，关系须明确从属。
- 用户角色决定功能权限，机构属性决定数据权限范围。
- 账号状态变更（启用/禁用/冻结）即时生效。
- 中心用户可管理全项目，分中心用户仅管理本分中心。

**验收标准**

- [ ] 机构 CRUD、层级与关系配置验证通过
- [ ] 用户账号创建/状态管理验证通过
- [ ] 角色权限与多中心隔离验证通过
