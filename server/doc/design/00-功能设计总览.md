> **文档版本**：V1.0  
> **上游文档**：[业务功能需求.md](../业务功能需求.md) · [功能需求清单.md](../功能需求清单.md)  
> **设计范围**：30 项 BR / 233 项 REQ 全量覆盖  
> **设计原则**：技术无关、逻辑组件化、需求可追溯

## 1. 设计目的

本文档体系在《业务功能需求说明书》基础上，给出共病专病科研平台的**功能级设计基线**，用于：

- 统一研发、测试、产品对系统边界与模块职责的理解
- 作为后续技术选型、详细设计与编码实现的输入
- 建立 BR → 设计章节 → REQ 的可追溯链路

**不包含**：具体部署脚本与代码实现（技术选型见 [08-技术架构推荐](./08-技术架构推荐.md)）。

## 5. 追溯规则

### 5.1 编号体系

```
功能要求.md / 功能要求.txt     原始招标规格
        ↓
功能需求清单.md (REQ-*)        233 条可跟踪功能项（研发/测试最小单元）
        ↓
业务功能需求.md (BR-*)         30 条业务需求（产品/验收单元）
        ↓
doc/design/*.md (FD-*)         功能设计（本体系，设计/架构单元）
```

### 5.2 追溯要求

- 每条 **REQ** 须在 [07-模块功能设计.md](./07-模块功能设计.md) 附录 A 中映射到至少一个设计子功能
- 每条 **BR** 须在 07 文档中有独立章节，且验收标准在「验收设计点」中给出设计对策
- 设计变更须同步更新 REQ 映射表并注明版本

### 5.3 设计文档引用格式

- 引用 BR：`[BR-01-01](../业务功能需求.md#br-01-01-多源数据采集与对接)`
- 引用 REQ：`REQ-01-01-01`（见功能需求清单）
- 引用设计章节：`FD-03-§7` 表示数据架构设计第 7 章

## 6. 核心设计约束

| 编号 | 约束 | 来源 |
| --- | --- | --- |
| DC-01 | 数据流必须遵循 Staging → Governance → Published，禁止绕过治理直写专病库 | BR-01-01 |
| DC-02 | EMPI 为跨系统患者关联唯一入口 | BR-01-04 |
| DC-03 | 专病库采用 core_fields + extended_fields 支持动态扩展 | NFR-09 |
| DC-04 | 原始数据不出库，分析在 ComputePlane 沙箱内完成 | NFR-02, BR-11-03 |
| DC-05 | 所有数据操作可审计、敏感字段分级加密 | NFR-03/04, BR-05-11 |
| DC-06 | 多中心数据按机构维度隔离，分中心不可越权 | BR-20-01, BR-05-10 |
| DC-07 | 共病库为规则驱动的逻辑视图，非独立冗余拷贝 | BR-05-05 |
