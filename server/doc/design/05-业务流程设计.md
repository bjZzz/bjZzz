## 2. BP-01 多源采集与入库

### 2.1 主流程

```mermaid
sequenceDiagram
  participant Admin as DataAdmin
  participant IG as IngestionGateway
  participant ST as StagingArea
  participant CL as CleaningService
  participant EM as EMPIService
  participant PB as PublishingService
  participant DB as PublishedDB
  participant MQ as RabbitMQ
  participant CB as ComorbidityDB
  participant IX as SearchIndex

  Admin->>IG: 配置数据源与同步策略
  IG->>ST: 拉取/接收原始数据
  ST->>CL: 触发清洗批次
  CL->>CL: 缺失/异常/重复/单位转换
  CL->>EM: 请求患者匹配
  alt 精确匹配
    EM-->>CL: empi_id
  else 模糊匹配
    EM-->>Admin: 待确认候选
    Admin->>EM: 确认/拒绝合并
    EM-->>CL: empi_id
  end
  CL->>PB: ReadyToPublish
  PB->>PB: 入库规则校验
  alt 规则通过
    PB->>DB: 写入专病库（三类）
    PB->>MQ: DataPublished
    MQ->>CB: ComorbidityViewRefresh
    MQ->>IX: IndexSyncRequired
  else 规则不通过
    PB->>ST: 标记 Rejected
  end
```

### 2.2 同步策略分支

| 策略 | 触发条件 | 行为 |
| --- | --- | --- |
| T+7 | 历史归档数据源 | 周级 Cron，全量或增量；支持 HL7 v2 适配 |
| T+1 | 日常诊疗数据 | 日级 Cron，增量快照 |
| 历史批量 | 回顾性队列导入 | 批量预审后入 Staging |
| 准实时 | Webhook / 日志监听 | 触发 RealtimeBatchReceived，分钟级入 Staging |
| DICOM | 影像元数据 | DicomAdapter 解析元数据入 Staging |
| 多中心 | 分中心上传 | integration upload → Staging |

### 2.3 异常分支

| 异常 | 处理 |
| --- | --- |
| 连接失败 | SyncJob → Failed，告警通知，支持重试 |
| 解析错误 | staging_record.parse_status=PARSE_ERROR，跳过或人工修正 |
| EMPI 无匹配且无候选 | 创建新 empi_id |
| EMPI 多候选 | 进入 match_candidate 待审核队列 |
| 入库规则不通过 | StagingBatch → Rejected，记录原因 |
| 映射失败 | 保留失败明细，支持人工修正后重试 |

### 2.4 领域事件与异步（RabbitMQ）

| 事件 | 消费者 | 行为 |
| --- | --- | --- |
| StagingBatchReceived | governance | 触发清洗流水线 |
| CleaningCompleted | governance | 进入发布前校验 |
| DataPublished | asset | 共病规则引擎刷新物化视图 |
| DataPublished | analytics | ES/MySQL 索引增量同步 |
| DictionaryChanged | asset, analytics | 缓存失效、索引字段映射更新 |
| RealtimeBatchReceived | ingestion | 准实时批次入 Staging |

详见 [DD-04 领域事件与异步设计](../detail/04-领域事件与异步设计.md)。

## 3. BP-02 CRF 录入与补录

### 3.1 主流程

```mermaid
sequenceDiagram
  participant User as ClinicalUser
  participant CRF as CRFService
  participant QC as QualityControl
  participant PB as PublishingService
  participant DB as PublishedDB

  User->>CRF: 打开 CRF 表单（双屏模式）
  Note over User,CRF: 左侧原始病历，右侧表单/时间轴
  User->>CRF: 填写答案
  CRF->>CRF: 逻辑跳转/量表计分
  CRF->>QC: 缺失指标校验
  alt 严重缺失
    QC-->>User: 阻断/高亮预警
    User->>CRF: 完善必填项
  end
  User->>CRF: 提交
  CRF->>QC: 格式与逻辑校验
  alt 补录场景
    QC->>User: 质控员审核
    User->>QC: 审核通过
  end
  CRF->>PB: 发布至 Published
  PB->>DB: 写入/更新专病记录
  CRF->>CRF: 记录变更历史
```

### 3.2 补录权限分支

| 角色 | 数据范围 |
| --- | --- |
| 分中心协调员 | 仅本分中心 org_id |
| 中心录入员 | 本机构及授权范围 |
| 质控员 | 审核权限，无直接写入 |

### 3.3 异常分支

| 异常 | 处理 |
| --- | --- |
| 表单版本过期 | 提示升级到新版本，草稿迁移 |
| 附件格式不支持 | 拒绝上传，提示支持格式 |
| 审核驳回 | 状态 → REJECTED，退回修改 |
| 越权补录 | 403，审计记录 |

## 4. BP-03 质控复核闭环

### 4.1 主流程

```mermaid
sequenceDiagram
  participant Sys as System
  participant QC as QualityControl
  participant Reviewer as QCReviewer
  participant Report as ReportService

  Sys->>QC: 定时六维质控扫描
  QC->>QC: 完整性/一致性/准确性/唯一性/时效性/稳定性
  alt 阈值突破
    QC->>Reviewer: 预警通知
  end
  Reviewer->>QC: 配置抽样策略
  QC->>QC: 生成样本数据集
  Reviewer->>QC: 发起差异比对
  QC->>QC: 专病库 vs 源系统并列展示
  QC->>Reviewer: 差异高亮 + 复核任务
  Reviewer->>QC: 在线审核判定
  QC->>QC: 更新 QualityIssue 状态
  QC->>Report: 月末生成综合报告
```

### 4.2 六维质控指标

| 维度 | 检测内容 | 默认阈值 |
| --- | --- | --- |
| 完整性 | 必填字段缺失 | 完整率 < 92% 预警 |
| 一致性 | 跨表/跨系统冲突 | 可配置 |
| 准确性 | 数值异常/逻辑错误 | 准确率 < 99% 预警 |
| 唯一性 | 重复患者/记录 | 可配置 |
| 时效性 | 数据更新延迟 | 可配置 |
| 稳定性 | 分布漂移 | 可配置 |

### 4.3 与下游流程衔接

| 质控结论 | 后续流程 |
| --- | --- |
| 需补录修正 | → BP-02 双屏补录 |
| 需重新采集 | → BP-01 定向重同步 |
| 跨专病差异 | 三类专病库并列比对（REQ-05-05-05） |

## 5. BP-04 检索与数据导出

### 5.1 主流程

```mermaid
sequenceDiagram
  participant User as Researcher
  participant Search as SearchExportService
  participant ES as Elasticsearch
  participant Auth as AuthService
  participant Audit as AuditService
  participant OA as OASystem
  participant Store as FileStore

  User->>Search: 构建检索条件
  Search->>Search: 逻辑组合/嵌套/跨病种
  alt ES 可用
    Search->>ES: 查询 idx_search_document
    ES-->>Search: 命中 empi_id 列表
  else ES 降级
    Search->>Search: MySQL idx 物化表查询
  end
  Search-->>User: 结果 + 节点患者数
  User->>Search: 筛选/排序/分组
  User->>Search: 创建导出任务
  Search->>Auth: 权限校验（含共病 L3）
  Search->>OA: 提交审核（可选）
  OA-->>Search: 审核通过
  Search->>Search: 脱敏/明文策略
  Search->>Store: 生成文件
  Search->>Audit: 记录导出审计
  Search-->>User: 下载链接
  opt 导入项目
    User->>Search: 导入科研项目（→ BP-05）
  end
```

### 5.2 导出格式分支

| 格式 | 用途 |
| --- | --- |
| Excel/CSV | 常规科研分析 |
| CDISC SDTM/ODM | 国际临床试验标准互操作 |
| 时间序列 | 全病程指标导出 |

### 5.3 异常分支

| 异常 | 处理 |
| --- | --- |
| 审核驳回 | ExportTask → Rejected |
| 超量导出 | 分批或拒绝，需更高级权限 |
| 无数据权限 | 403 |
| 导出失败 | Failed，支持重试 |
| ES 不可用 | 自动降级 MySQL，记录告警 |

### 5.4 Elasticsearch 检索与索引同步

```mermaid
flowchart LR
  publish[DataPublished] --> mq[RabbitMQ]
  mq --> sync[IndexSyncConsumer]
  sync --> es[(Elasticsearch)]
  sync --> chk[idx_sync_checkpoint]
  user[检索请求] --> router{ES健康?}
  router -->|是| es
  router -->|否| mysql[(MySQL_idx)]
```

- 索引命名：`nanda-search-{orgId}`
- 全量重建：XXL-JOB `indexFullRebuild`（维护窗口）
- 与 BP-01 发布流水线通过 `IndexSyncRequired` 事件衔接

## 6. BP-05 科研队列与随访

### 6.1 主流程

```mermaid
sequenceDiagram
  participant PI as ProjectLead
  participant Proj as ProjectService
  participant Cohort as CohortService
  participant Search as SearchExportService
  participant FU as FollowUpService
  participant Notify as NotificationService

  PI->>Proj: 创建项目（选择设计模板）
  Proj->>Proj: 加载纳排配置项
  PI->>Cohort: 创建队列 + 纳排规则
  Cohort->>Search: 自动筛选符合条件患者
  Search-->>Cohort: 候选列表
  Cohort->>Cohort: 批量入组
  opt 前瞻性研究
    PI->>Cohort: 随机分组
  end
  PI->>FU: 配置随访阶段与 CRF
  FU->>FU: 生成 FollowUpTask
  FU->>Notify: 到期提醒
  loop 随访执行
    Notify->>PI: 待随访/逾期通知
    PI->>FU: 执行随访 + 填写 CRF
    FU->>FU: 更新任务状态
  end
  PI->>Proj: 设计一致性校验
  alt 偏离预设
    Proj->>PI: 预警
  end
```

### 6.2 队列动态维护

- 专病库数据更新 → 自动同步 cohort_member 关联数据
- 纳排规则变更 → 可选重新筛选（新增/移除提示）

### 6.3 异常分支

| 异常 | 处理 |
| --- | --- |
| 纳排结果为空 | 提示调整规则 |
| 随机分组失败 | 人数不足告警 |
| 随访逾期 | 状态 → Overdue，通知升级 |
| 设计偏离 | 项目预警，不阻断但记录 |

## 7. BP-06 沙箱分析

> **边界**：通用统计工作台、Notebook 探索、个性化脚本；**结构化风险模型与 PDF 报告**见 BP-07。

### 7.1 主流程

```mermaid
sequenceDiagram
  participant User as Researcher
  participant App as AnalyticsService
  participant Queue as AnalysisJobQueue
  participant SB as SandboxRuntime
  participant Pub as PublishedDB
  participant Audit as AuditService

  User->>App: 提交分析请求
  App->>App: 权限校验
  App->>Queue: 入队 AnalysisJob
  Queue->>SB: 分配 K8s Pod
  SB->>Pub: 数据集只读挂载（Parquet）
  SB->>SB: 执行统计/脚本/共病网络
  SB->>SB: 结果脱敏
  SB-->>App: 聚合结果
  App->>Audit: 记录分析审计
  App-->>User: 返回图表/指标
  Note over SB: 禁止原始数据 download
```

### 7.2 分析类型分支

| 类型 | 入口 | 执行环境 |
| --- | --- | --- |
| 描述/检验/回归/生存 | StatisticsService | Sandbox |
| 共病网络/因果分析 | ComorbidityAnalysisService | Sandbox |
| Python 脚本 / Notebook | SandboxRuntime Web IDE | K8s Pod |
| 独立 Excel 数据集 | StatisticsService | Sandbox（隔离存储） |

### 7.3 安全约束

- 沙箱无 outbound 数据 API（NetworkPolicy）
- 结果仅含聚合/脱敏数据
- 动态水印覆盖展示层
- 脚本上传前 AST 安全扫描

### 7.4 异常分支

| 异常 | 处理 |
| --- | --- |
| 资源紧张 | 排队等待，通知预计时间 |
| 脚本执行超时 | 终止 Pod，返回错误 |
| 脚本安全扫描失败 | 拒绝执行 |
| 参数不足 | 422，提示缺失字段 |

## 8. BP-07 风险评估与评估报告

### 8.1 主流程

```mermaid
sequenceDiagram
  participant User as Researcher
  participant Search as SearchExportService
  participant Risk as RiskAssessmentService
  participant SB as SandboxRuntime
  participant Store as ResultStore
  participant PDF as PdfReportGenerator
  participant Audit as AuditService

  User->>Search: 圈选患者/队列（或从 BP-05 导入）
  User->>Risk: 选择风险模型（10 类）
  Risk->>Risk: 参数校验与缺失提示
  Risk->>SB: 提交模型计算 Job
  SB->>SB: RiskCalculatorFactory 执行
  SB-->>Risk: 评分/分层结果
  Risk->>Store: 写入 ana_risk_assessment
  User->>PDF: 生成评估报告
  PDF->>PDF: 嵌入图表（脱敏）
  PDF->>Store: MinIO 存储 PDF
  Risk->>Audit: 审计留痕
  PDF-->>User: 下载/预览（水印）
```

### 8.2 风险模型分支

| 模型类别 | 示例 REQ |
| --- | --- |
| 心血管 | ASCVD、Framingham、CHA₂DS₂-VASc |
| 呼吸 | GOLD、CAT、BODE |
| 代谢 | FINDRISC |
| 共病 | Charlson、Elixhauser |

### 8.3 异常分支

| 异常 | 处理 |
| --- | --- |
| 必填参数缺失 | 422，高亮缺失字段 |
| 模型不适用 | 提示病种/人群不匹配 |
| 计算超时 | Job Failed，支持重试 |
| PDF 生成失败 | 保留数值结果，报告状态 Failed |

## 9. BP-08 外部集成与结果回传

### 9.1 主流程

```mermaid
sequenceDiagram
  participant Ext as ExternalSystem
  participant INT as IntegrationGateway
  participant FHIR as FhirProvider
  participant ANL as AnalyticsService
  participant AST as AssetService
  participant Audit as AuditService

  opt FHIR 读
    Ext->>INT: GET /integration/fhir/Patient
    INT->>FHIR: 映射 R4 资源
    FHIR-->>Ext: Patient/Observation Bundle
  end
  ANL->>INT: 评估/导出结果就绪
  INT->>INT: 组装 writeback payload
  INT->>Ext: POST 外部回传接口
  alt 成功
    INT->>Audit: int_writeback_log SUCCESS
  else 失败
    INT->>INT: 指数退避重试
    INT->>Audit: FAILED + 告警
  end
  opt 共病库外部回传
    AST->>INT: 共病视图快照 payload
    INT->>Ext: REQ-05-02-13 协同回传
  end
```

### 9.2 集成类型分支

| 类型 | 方向 | 说明 |
| --- | --- | --- |
| 分中心 upload | 入 | Excel → Staging（衔接 BP-01） |
| FHIR R4 读 | 出（对外提供） | Patient、Observation |
| 评估结果 writeback | 出 | 风险报告、导出摘要 |
| 共病回传 | 出 | 物化视图快照 |

### 9.3 异常分支

| 异常 | 处理 |
| --- | --- |
| 外部系统不可达 | 重试队列，达上限告警 |
| FHIR 映射错误 | 400 + 结构化 OperationOutcome |
| 回传鉴权失败 | 401/403，审计 |
| payload 校验失败 | 拒绝发送，保留草稿 |
